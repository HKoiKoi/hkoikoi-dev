# hkoikoi.dev MVP PRD

## 🎯 핵심 정보

**목적**: 학력·경력·프로젝트 등 개인 이력을 한 곳에 공개하고, 관리자 본인이 마크다운(LaTeX, raw HTML)으로 블로그 글을 직접 작성·발행한다.
**사용자**: 방문자(채용 담당자·동료 개발자)는 열람만 하고, 관리자 1인(hkoikoi)만 블로그 글을 작성한다.

**연락처**: 이메일 koikoilove99@gmail.com, GitHub https://github.com/hkoikoi

## 🚶 사용자 여정

```
[방문자]
1. 메인
   ↓ 헤더 메뉴 / 섹션 바로가기 카드 / 대표 프로젝트 카드 / 최신 글 카드

2. 학력 | 경력 | 자격증 | 사회봉사 | 어학 | 사회활동 | 프로젝트 | 논문
   ↓ 헤더 메뉴로 상호 이동, 로고 클릭 시 메인

3. 블로그 목록
   ↓ 카테고리/태그 클릭 → 같은 페이지에서 필터 적용
   ↓ 글 카드 클릭

4. 블로그 상세
   ↓ 태그/카테고리 클릭 → 블로그 목록(필터 적용), 로고 → 메인

[관리자]
5. 로그인 (헤더 메뉴 없음, 직접 진입)
   ↓ 인증 성공 + 관리자 권한 → 관리자 글 목록
   ↓ 실패 → 오류 표시 유지

6. 관리자 글 목록 (초안·발행 전체)
   ↓ [새 글] → 글 편집기(작성)
   ↓ [수정] → 글 편집기(수정)
   ↓ [삭제] → 확인 후 목록 갱신
   ↓ [로그아웃] → 메인

7. 글 편집기
   ↓ 저장 성공 → 관리자 글 목록
   ↓ 슬러그 중복/검증 실패 → 폼에 오류 표시

비로그인 또는 관리자 아님 상태로 관리자 영역 접근 → 로그인(비로그인) / 없는 페이지 처리(일반 계정)
```

## 📝 가정 사항

- 정적 8개 섹션의 실제 이력은 아직 제공되지 않았다. 샘플 문구로 채우고 `// TODO`로 표기하며, 사용자가 실제 내용으로 교체한다. 실제 이력은 PRD에 작성하지 않는다.
- 블로그 글 주소는 사용자 확정 결정에 따라 `/blog/{slug}` 형식(블로그 하위 + 슬러그)이다(요구사항의 최상위 제목 경로는 고정 페이지와 충돌 가능해 변경). 슬러그는 한글 허용·수정 가능.
- 인증은 관리자 1인 로그인 용도로만 포함한다. 방문자 계정·회원가입·프로필은 없다. 관리자 계정 생성과 Supabase "신규 가입 허용" 해제는 사용자가 대시보드에서 직접 수행한다(2026-10-26 수행 완료: 계정 생성, `app_metadata.role = admin` 부여, 가입 해제, 최소 비밀번호 12자·대소문자·숫자·기호 필수).
- 글 편집기는 작성/수정을 하나의 페이지로 처리한다.
- 카테고리는 글에 문자열로 저장하며 별도 카테고리 모델은 두지 않는다.
- 모바일 폭과 라이트/다크 모두 지원한다.

### 알려진 트레이드오프

- **`<style>` 허용**: 글의 CSS가 해당 페이지 전체에 영향을 줄 수 있다. 작성자가 관리자 1인이라 수용하고, 본문 컨테이너 래퍼로 범위를 문서화한다. 스코프 변환은 MVP 밖.
- **raw HTML sanitize 정책**: 기본 스키마를 확장해 `style`, `figure/figcaption` 태그, `post-` 접두 class(+ math·언어 클래스), 이미지 속성(`loading/width/height`)을 허용하고 `script`, `on*` 이벤트, `javascript:` URL은 제거한다(`details/summary`는 기본 허용). 기본 스키마가 class를 지우고 id에 `user-content-` 접두를 붙이므로, 작성자는 `post-` class로 `<style>`과 연결하고 id 선택자는 `#user-content-{id}`로 쓴다. sanitize를 KaTeX 렌더 앞에 둬 수식 출력의 대량 허용을 피하며 KaTeX `trust`는 켜지 않는다. 이 동작과 "class가 붙은 요소에 `<style>` 규칙이 실제 매칭됨"을 단위 테스트로 고정한다.
- **스타일 변조 위험**: `<style>`로 `position:fixed` 오버레이, `url()` 외부 요청(방문자 IP 추적) 등이 가능하다. 작성자 1인 전제에서 수용하되 편집기 미리보기는 격리하고 관리자 계정은 강한 비밀번호(가능하면 MFA)로 보호한다.
- **없는 글 응답 코드**: 스트리밍 이후 `notFound()`라 HTTP 200 + noindex로 응답한다(soft 404). MVP에서는 수용한다.
- **역할 회수 지연**: 관리자 role을 회수해도 이미 발급된 JWT는 만료 전까지 유효하다(RLS도 동일).
- 스토리지 고아 파일은 정리하지 않는다(삭제·교체된 이미지가 남음).
- **유출 비밀번호 보호 미적용**: Supabase의 유출 비밀번호 보호(`auth_leaked_password_protection`)는 Pro 플랜 전용이라 쓰지 않는다. 회원가입 차단과 강한 비밀번호 정책(12자 이상, 대소문자·숫자·기호 필수)으로 완화하고, advisor 경고 1건은 예외로 수용한다.
